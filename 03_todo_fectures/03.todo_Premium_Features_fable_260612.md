## 1. 為什麼這條路最省事（vs Lode 的痛）

- **不用寫 ObjC FFI bridge**：Lode (Tauri/Rust) 估 5–6 天；SW 是 SwiftUI native + min iOS 26 → StoreKit 2 async/await 直接用，code 約 0.5–1 天。
- **不用自己 parse receipt**：`Transaction.currentEntitlements` 取代 Lode 計畫中的 PKCS#7/ASN.1 手工解析，且離線可用。
- **Apple = merchant of record**：EU 退貨權（right of withdrawal）、VAT、發票、退款全由 Apple 處理 — Lode direct sale（LemonSqueezy）要自己扛的那堆，IAP 路線天然沒有。
- **歐美「填資料」大多是帳號層級、已經辦過**：DSA trader status 在 SW 1.0 上架 EU 時已申報；Paid Apps Agreement / 銀行 / 稅表辦一次全帳號共用 → §4 只是「確認是綠的」。
- **Made for Kids 已過審**：上次 Guideline 1.3/2.1 的資料問題已答過且過關，這次 IAP 送審把同一套答案寫進 Review Notes 預防再問。

## 2. 合規查證結果（2026-06-12，web 查證）

1. **Kids Category（Guideline 1.3）**：purchasing opportunities 必須在 **parental gate 之後** → SW 的 Settings 本來就 gate 在入口（HomeView 齒輪 → ParentalGateView 成人乘法題），Pro 區放 Settings 內 = 天然合規。臨時解鎖視窗（temporary unlock）也是先過 gate 才能啟動，OK。
2. **Kids Category 禁第三方 analytics / 廣告** → SW 沒有任何第三方 SDK，維持現狀即可。StoreKit 是 Apple 自家框架，不算第三方。
3. **DSA trader status（EU）**：有收費 = 定義上的 trader，需在 ASC 完成驗證（地址/電話/email 會公開顯示在 EU 產品頁）。2025-02-17 起未申報的 app 已從 EU 下架 — SW 現在在架上代表已申報，**只需確認狀態 verified**。
4. **App Privacy 維持「Data Not Collected」**：Apple 對 collect 的定義 = 資料傳離裝置且開發者（或其夥伴）可存取。StoreKit 交易由 Apple 處理、entitlement 留在裝置上，開發者收不到任何個資 → 不用改 privacy label，也不用改 privacy policy 的「不收集資料」主張（可加一句「購買由 Apple 處理」更穩）。
5. **Restore 機制必備**（non-consumable 審核要求）→「回復購買」按鈕 + `AppStore.sync()`。
6. **Ask to Buy**：兒童 Apple ID 購買會進家長核准流程 → `purchase()` 回 `.pending`，UI 要有「等待家長核准」狀態，核准後由 `Transaction.updates` 自動解鎖。
7. **IAP 首次送審必須隨某個 app version 一起送**（binary 引用的 IAP 要先到 Ready to Submit，否則 metadata rejected）。

### 3.1 新檔 `SunnyWalker/Services/StoreService.swift`

```swift
// 結構（非完整 code）
@MainActor
final class StoreService: ObservableObject {
    static let shared = StoreService()
    static let proProductID = "app.rexcode.sunnywalker.pro.lifetime"

    @Published private(set) var isPro: Bool
    @Published private(set) var product: Product?          // nil = 還沒載到（離線）
    @Published private(set) var purchaseState: PurchaseState // idle/purchasing/pendingAskToBuy/purchased/failed(msg)

    func start()                 // app 啟動呼叫：開 Transaction.updates listener + refreshEntitlement() + loadProduct()
    func loadProduct() async     // Product.products(for:) — 失敗保持 nil，ProUpgradeView 開啟時重試
    func purchase() async        // product.purchase() → .success(verified) → transaction.finish() + refresh
                                 //                    → .pending → purchaseState = .pendingAskToBuy
                                 //                    → .userCancelled → 無聲返回 idle
    func restore() async         // try await AppStore.sync() + refreshEntitlement()
    func refreshEntitlement() async
    // for await result in Transaction.currentEntitlements:
    //   verified && productID == proProductID && revocationDate == nil → entitled
    // 寫入 UserDefaults "isProUnlocked"（StoreService 是唯一寫入者）
}
```

要點：
- **listener 必須在 app 啟動就開**（先於任何 UI），漏掉會吃不到 Ask-to-Buy 核准 / Family Sharing / 退款 revocation 的非同步 transaction。掛在 `SunnyWalkerApp` init 的 `Task { for await result in Transaction.updates { ... } }`。
- 離線：`currentEntitlements` 走本地 cache，已購用戶斷網照樣 Pro。
- Refund/revocation：`revocationDate != nil` → isPro = false（限制恢復，但**不刪**超量資料：第 7+ 顆鬧鐘保留、只擋「再新增」，與現有 guard 行為一致）。
